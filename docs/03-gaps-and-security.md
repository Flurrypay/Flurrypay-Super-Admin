# API gaps and security findings

These findings came from reading the API. Most are now fixed on the API branch **`admin-console-hardening`** (in `../api`, uncommitted, not merged or deployed). The **Status** column says where each one stands. "Branch" means the fix is on that branch and covered by its integration harness or type check; "Open" means it is not addressed yet. Deployment steps and breaking changes are in `api/docs/admin-console-hardening.md`.

## Security findings

## Data-accuracy findings

| #   | Finding                                                                                                                                               | Where                                                                       | How the console handles it                                                                                                                                                                                                          |
| --- | ----------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| D1  | `totalTransactionVolume` is `SUM(amount)` across all currencies.                                                                                      | `services/transaction.service.ts`                                           | Not displayed. Reports sum per currency with exact `numeric` totals.                                                                                                                                                                |
| D2  | `totals` on `/transactions/admin/all` are page-local (except `totalTransactions`), and `totalAmount` mixes currencies.                                | `controllers/transactions.controller.ts`                                    | Not displayed. Counts use the paginated `total`; Reports use `GET /reports/transactions`.                                                                                                                                           |
| D10 | A transaction's amount was shown with no connection to the balance it produced, so "their balance is X, why?" could not be answered from the console. | `controllers/transactions.controller.ts`                                    | **Fixed.** Each row carries `walletMovement` — `balanceBefore`/`balanceAfter` from `wallet_ledger`, joined on `reference`, with each entry listed. Null (not zero) when no naira moved, and a flag when the entries do not join up. |
| D3  | The financial dashboard's "today/month" boundaries use the API server's local time, and its counts are admin transfers, not customer transactions.    | `services/adminFinancialService.ts`                                         | Not used. Overview and Reports compute WAT days (the database groups by `Africa/Lagos` day).                                                                                                                                        |
| D4  | Timestamps are `timestamp without time zone`; correct UTC depends on the API process running in UTC.                                                  | models                                                                      | Assumed UTC. | D6  | Crypto balances from `/user-wallet-addresses` are pre-rounded, and naira values are live re-pricings.                                                 | `walletController`                                                          | Labelled as display values and estimates.                                                                                                                                                                                           |
| D7  | Admin notifications were returned unsorted and unbounded, and the empty case had no array at all.                                                     | `services/adminNotification*`                                               | **Fixed.** Ordered newest-first and paged server-side (`page`, `limit`, `unread`); the shape is the same whether or not there is anything in it.                                                                                    |

| D9  | Earnings breakdown and stranded-transfer totals are summed in JavaScript floating point.                                                              | `adminFinancialService.getEarningsBreakdown`, `strandedTransfer.service.ts` | Shown with a note that totals may differ from an exact sum by a fraction of a kobo. | G16 | Reports                                           | **Branch:** `GET /reports/transactions`, `GET /reports/users`.                                                                                                                                                                                                                                                                                                |

## Database

- The branch adds a tracked, idempotent migration: `migrations/1794000000000-AdminConsoleHardening.ts` (new `admin` columns, `admin_roles`, structured `admin_audit_logs` columns and an index on `targetId`).
- Still true: `userAssets.balance` is `float`, several balances are `varchar`, and `synchronize: true` runs in production (see `01-database-domain-map.md`).

## Modules not yet in the console

Trade queue, OTC tracker, broadcasts, campaigns, banners, careers, payout-provider switching and configuration (read-only in Treasury), transacting-user monitoring and proof-of-funds review. They can be added on the same foundations.

Now surfaced: the **support inbox** and live chat (`/support`), the **notification list** (`/notifications`), per-customer **ledger reconciliation** inside Users → Wallets, **transaction flags** across the ledger views, and in Treasury the **crypto reserves** (with withdrawals and deposit addresses), **payout-provider switching and syncing**, and the company's own **money in and out**.
